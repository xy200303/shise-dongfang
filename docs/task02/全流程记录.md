# Task 02 全流程产品说明记录

> 交付物之一：产品动机、设计理念、Miora 与 CodeBuddy 的具体产出。
> 产品：拾色 · 东方 ｜ 演示：https://shise.xyun.dev ｜ 仓库：https://github.com/xy200303/shise-dongfang

## 1. 产品动机

中国传统色资源丰富，但现有工具大多停留在「色值列表」层面——好看，却不可用。
设计师真正需要的是：看到一只传统色，就能立刻知道它在真实界面里怎么用——
它的 10 级色阶长什么样、配什么灰、和哪些色和谐、当主题色时组件效果如何、文字对比度是否达标。

「拾色 · 东方」把 Task 01 的 OKLCH 色阶引擎装进传统色主题馆：
**每一只传统色都不是一个死色值，而是一套可即取即用的、经过感知均匀与可访问性校验的设计系统种子。**

## 2. 设计理念

- **墨分五色**：界面灰阶为跟随主题色色相的「墨阶」（14 级中性色阶），数字时代的中国画墨法
- **随类赋彩**：页面外壳保持宣纸/玄色中性，色彩让位给传统色本身
- **宋式极简**：留白、衬线标题、hairline 分隔、克制动效
- **以色造物**：衣物物件皆参数化模板，部件按角色（主/辅/缘/系/里/纹）登记，配色不手调，
  由引擎把基色推演成整案——配色规则（顺承/对比/五色/节气）译成引擎调用
- **可访问性内置**：主题切换后经 WCAG 2.x + APCA 双轨校验，文字反色自适应、品牌文字色自动下沉

| 主题 | 任一传统色一键设为全站主题（引擎色阶替换 TDesign Token），亮/暗双模式重新生成 |

## 5. CodeBuddy 的具体产出

按《CodeBuddy-研发任务包.md》开发并全部落地，关键工程：

- **引擎消费线**：shise-engine 以 git 依赖 `#v1.2.0` tag 锁定安装，主题色切换 = 引擎色阶替换
  TDesign 色彩 Design Token，亮/暗重新生成
- **手写 WebGL 双场景**：星图 3D 漫游（OKLCH 点云 + sRGB 色域壳）、釉色器物（MatCap 程序化釉面）
- **造物系统**：参数化模板 + 配色求解器 + 纹样库（云纹/回纹/缠枝）+ 设计稿 PNG 导出
- **OKLab 聚类染色引擎**（`src/zaowu/svgdye.ts`）：SVG 路径/位图像素两路，分族换染保留明暗细节
- **3D 试穿间**：KayKit CC0 人台 UV 调色板格级染色、三场景三动画
- **混元图生 3D 接入**：油纸伞 GLB 23MB→1.2MB（weld+simplify 7.5 万面/贴图 1024/meshopt），
  baseColor 贴图 OKLab 分族软 mask 染色（单次 <50ms），与程序化伞并列呈现
- 数据集校验脚本（537 色交叉核对、265 条真实诗词）、GitHub Actions 自动部署
